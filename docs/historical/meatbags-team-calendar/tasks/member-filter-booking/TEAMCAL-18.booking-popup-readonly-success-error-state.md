# TEAMCAL-18 — Booking popup UX: read-only контекст + success/error state

Статус: done

## Описание
Доработать booking popup под новый UX:
- показывать read-only контекст (на кого бронируется + дата/время);
- динамический заголовок (`команда`/`участник`);
- после успеха оставаться в попапе и показывать финальный текст;
- при ошибке оставлять заполненную форму и показывать тост.

## Scope
- Перестройка состояния `useTeamPageBooking` в state machine:
  - `editing`
  - `submitting`
  - `success`
  - `error` (с сохранением формы)
- Обновление `TeamBookingModal`:
  - динамический заголовок;
  - read-only имена target-участников;
  - read-only дата/время выбранного слота;
  - скрытие формы при success.
- Интеграция payload в `/api/booking` с `selectedMemberPublicIds`/`selectionMode`.
- Поведение уведомлений:
  - success: без тоста;
  - error: тост, форма сохранена.
- Frontend unit-тесты на новую логику попапа.

## Критерии готовности
- Заголовок попапа соответствует выбранному режиму.
- До отправки виден read-only контекст + форма.
- После success форма исчезает, показывается текст:
  - `Встреча запрошена, команда скоро создаст встречу в календаре.`
- Попап не закрывается автоматически.
- При `500/502` форма остается заполненной и показывается error-toast.

## Тест кейсы
1. Режим `single` => заголовок с именем участника.
2. Режим `all` => заголовок с названием команды.
3. До отправки отображаются имена target и дата/время слота.
4. Успешная отправка => success-state без тоста и без автозакрытия.
5. Ошибка отправки => форма сохранена, error-toast показан.
6. Повторная отправка после ошибки работает.
