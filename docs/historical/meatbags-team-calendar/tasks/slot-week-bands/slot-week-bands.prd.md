# Понимание задачи (PRD): Week bands для быстрого выбора слота

Дата: 2026-04-10

## Полезное действие
Пользователь открывает список доступных слотов и одним взглядом понимает, где заканчивается одна неделя и начинается другая, не теряя фокус на конкретных временах, по которым нужно кликнуть.

## Контекст (точка А)
- В продукте уже есть техническая группировка слотов по неделям в `implementation/app/_components/team-page/team-page-utils.ts` и `implementation/app/_components/team-page/team-page-client.tsx`.
- Визуально эта группировка почти не читается: недели ощущаются как тот же поток дней, а не как навигационные секции списка.
- Из-за этого список читается как длинная простыня, и пользователь тратит лишнее внимание на локализацию себя в диапазоне дат до выбора слота.
- Продуктовая цель экрана не меняется: главное не "изучить календарь", а быстро выбрать время и нажать на слот.
- Пользователь явно зафиксировал ограничение: экран должен оставаться единым, без аккордеонов, переключателей недель и скрытого контента.

## Цель (точка Б)
Список слотов остаётся на одном экране и полностью раскрытым, но неделя становится хорошо считываемой секцией списка: пользователь сразу видит границы недель, при этом самые заметные и кликабельные элементы по-прежнему остаются слотами времени.

## Метрики успеха
- Пользователь за 1-2 секунды понимает визуальные границы недель без чтения каждой строки дней.
- Слот остаётся главным CTA-объектом на экране и не проигрывает по контрасту week header-у.
- Список слотов не требует дополнительных взаимодействий для просмотра всех доступных дат.
- Текущая неделя считывается быстрее, но не превращается в доминирующий декоративный блок.

## FFF-рамка (Fixed time, Fixed budget, Flex scope)
- Fixed time: один небольшой UI polish slice в текущем public team-page потоке.
- Fixed budget: без изменений API, доменной логики availability и без перестройки day-level IA.
- Quality (не флексим): один экран, без скрытия контента; неделя читается сразу; слот остаётся главным интерактивным элементом; sticky-поведение не ломает usability.
- Flex scope (можно резать): отдельная переработка day headers, дополнительные метки типа "самые ранние слоты", анимационные polish-эффекты.

## MVP scope (минимально работоспособное полезное действие)
- [ ] Усилить визуальное разделение week sections в `SlotsView`
- [ ] Сделать компактный sticky week header для каждой недели
- [ ] Оставить все дни и слоты раскрытыми на одном экране
- [ ] Сохранить умеренный акцент недели, не конкурирующий со slot cards
- [ ] Ввести отдельный визуальный акцент для текущей недели, более мягкий, чем для CTA-элементов
- [ ] Зафиксировать тестами week-level markup contract для списка слотов

## Non-scope (не делаем в MVP)
- Переключатель недель, табы или аккордеоны
- Скрытие дней или слотов вне активной недели
- Переработка day header-ов как отдельного навигационного слоя
- Изменение логики группировки слотов, сортировки или availability
- Новые фильтры, бейджи "лучший слот", приоритизация по участникам

## Ограничения и риски
- Слишком сильный week accent навредит главной цели экрана: пользователь начнёт смотреть на контейнеры недель вместо выбора времени.
- Sticky header может съедать полезное пространство и перекрывать начало контента, если сделать его слишком высоким.
- Если нарастить новую UI-логику прямо в `team-page-client.tsx`, можно усугубить проблему oversized host file.
- Чисто CSS-решение без явного week-band hierarchy может снова дать "формально есть, визуально не читается".

## Открытые вопросы
- Нужен ли в текущем MVP отдельный компактный label для недель дальше второй (`Через неделю` / `Неделя 21-27 апр.`), или пока достаточно текущей логики `Эта неделя` / `Следующая неделя` + диапазон.
